## 问题分析

从截图现象：大量 `Warning!`，部分 `Danger!`前面多出小方框乱码，说明 **串口发送字节长度写死错误** ，是核心 bug。

```c
HAL_UART_Transmit(UART_Handle,Data,10,HAL_MAX_DELAY);
```

你这里固定写死发送 `10` 个字节。

```c
#define WarnNews "Warning!\n\r"   // "Warning!\n\r" 实际字符： W a r n i n g ! \n \r
//数一下：W(1)a(2)r(3)n(4)i(5)n(6)g(7)!(8)\n(9)\r(10) → Warning!\n\r刚好10字节

#define DangerNews "Danger!\n\r"  // D a n g e r ! \n \r
// D(1)a(2)n(3)g(4)e(5)r(6)!(7)\n(8)\r(9) → 只有9字节！！
```

`DangerNews` 字符串实际长度是 **9 字节** ，但是你强制发送 10 字节。

> 当发送 Danger 时：HAL\_UART\_Transmit 从字符串首地址开始往外读 10 个字节，字符串本身只有 9 个有效字节， **第 10 字节读取到字符串后面内存里的随机垃圾值** ，这个垃圾字节打印出来就是你看到前面那个方框乱码 `□Danger!`。

## 第二个隐患：xTaskNotifyWait 使用错误

```c
xTaskNotifyWait(~0,~0,&Value,portMAX_DELAY);
```

`xTaskNotifyWait` 前两个参数是 **清除掩码** ，不能直接填 `~0` 。

- ulBitsToClearOnEntry：进入函数时清除哪些通知位；
- ulBitsToClearOnExit：拿到通知后清除哪些位。

`~0` 是全部位，这会把通知值直接清 0，逻辑会出异常。 你是用通知值传数字（2=Warn,3=Danger），正确写法：

```c
xTaskNotifyWait(0, 0, &Value, portMAX_DELAY);
```

> `0` ：进入 / 退出不自动清除通知，拿到 Value 之后业务代码自己处理。 如果用 `~0` ，不等你判断，通知值直接被清零，极端情况拿不到正确 Value。

## 第三个小问题：字符串传参

```c
void UART_TransNews(void* string)
{
    uint8_t *Data=string;
    HAL_UART_Transmit(UART_Handle,Data,10,HAL_MAX_DELAY);
}
```

硬编码长度 10 是根源。 **不要写死长度，改用 strlen 获取字符串实际长度** 。

### 修改后的完整代码片段

```c
#include <stdint.h>
#include <string.h>   // 必须加strlen头文件
#include "stm32f1xx_hal.h"
#include "My_UART.h"

#include "cmsis_os.h"
#include "FreeRTOS.h"
#include "task.h" 

extern UART_HandleTypeDef huart1;
UART_HandleTypeDef *UART_Handle=&huart1;

#define WarnNews "Warning!\n\r" 
#define DangerNews "Danger!\n\r"

#define Warn 2
#define Danger 3

void UART_TransNews(char* string)
{
    uint16_t len = strlen(string);  // 获取字符串真实字节数
    HAL_UART_Transmit(UART_Handle, (uint8_t*)string, len, HAL_MAX_DELAY);
}

void My_UARTTask(void*params)
{
    uint32_t Value; // xTaskNotify输出是uint32_t，不要用int
    while(1)
    {
        do 
        {
            // 修正掩码，不自动清零通知
            xTaskNotifyWait(0, 0, &Value, portMAX_DELAY);
        }
        while(Value!=Warn && Value!=Danger);
        
        if(Value==Warn)
        {
            UART_TransNews(WarnNews);
        }
        else if(Value==Danger)
        {
            UART_TransNews(DangerNews);
        }
        vTaskDelay(pdMS_TO_TICKS(1000)); // 建议用pdMS_TO_TICKS，可读性更好
    }    
}
```

## 为什么会出现方框乱码完整复现

1. `WarnNews` 刚好 10 字节，读 10 字节刚好全部有效，没有乱码；
2. `DangerNews` 只有 9 字节，强制读 10 字节，第 10 字节是字符串常量后面内存的随机残留字节；
3. 这个无效不可打印字节，串口助手就显示成方框 `□` ，所以你看到： `□Danger!`。

> 补充： `xTaskNotifyWait(~0,~0,&Value,portMAX_DELAY);`这个 bug 不一定每次复现，但会偶发收不到通知，建议一并修复。
